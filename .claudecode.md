## 2. TECHNICAL STACK SKILLS (MANDATORY)

### **A. PHP & Symfony Standards**
- **Strict Typing:** Always use `declare(strict_types=1);` in new or refactored files.
- **Dependency Injection:** Use constructor injection only. Avoid `ContainerInterface`.
- **Attributes:** Use PHP Attributes for routing, validation, and Doctrine mapping (no annotations).
- **Service Layer:** Controllers MUST be thin. All business logic goes into `Service`, `UseCase`, or `Action` classes.
- **Voters:** Centralize all security and permission logic in Symfony Voters.

### **B. Data & Performance (Doctrine)**
- **Query Optimization:** Prohibit N+1 problems. Every repository method must use `addSelect` for related entities in lists.
- **DTOs:** Use Data Transfer Objects for complex forms or API responses to decouple the Database from the View.
- **Lazy Loading:** Be critical of lazy loading in loops; suggest `fetch="EAGER"` or Join strategies where strictly necessary.

### **C. Modern UX (The "Life-Facilitator" Layer)**
- **Symfony UX:** Prioritize **Twig Components** and **Live Components** to avoid full page reloads.
- **Stimulus/Turbo:** Use Turbo Streams for real-time UI updates (e.g., updating a price or status without refreshing).
- **Form UX:** - Implement "Smart Defaults" based on previous entries or user history.
    - Propose "Autosave" or draft states for long forms.
    - Use `EntityType` with `autocomplete => true`.

## 3. TOKEN EFFICIENCY & MEMORY MANAGEMENT

### **A. Scanning & Context Rules**
- **Ignore List:** Do NOT index or read `/vendor`, `/var`, `/public/bundles`, `/node_modules`, or `/tests` (unless explicitly asked).
- **Diff-Only Mode:** When proposing changes, provide only the `diff` or the specific modified method/block to minimize output length.

### **B. "State of Mind" Memory**
- **UX Debt Log:** Maintain a virtual log of "User Pain Points". Every time you find a complex controller or a confusing flow, flag it.
- **Style Consistency:** Follow the existing naming convention (naming_strategy) and language used in the codebase (Spanish/English).

---

## 4. OPERATIONAL UX STRATEGY (The "Client-First" Rules)

Whenever you analyze a feature, you **MUST** evaluate it against these 4 "Life-Facilitator" questions:
1. **Can we automate this?** (e.g., extracting data from an image/PDF via OCR/AI instead of manual typing).
2. **Is this step necessary?** (e.g., can we skip a screen or merge steps?).
3. **Does the user have clear feedback?** (e.g., progress bars, clear success/error states, avoiding "blank" processing times).
4. **Is it configurable?** (e.g., if a value like a tax or a category changes, can the client edit it from a UI settings panel without a dev?).
